TAP, br-agent & nftables Zero-Trust Egress

How an orb reaches GitHub and Google APIs while remaining completely blind to your LAN, Tailnet, and host services—and why nixos-rebuild switch doesn't drop its network.

Mission tie-in: Enforcing hard network isolation boundaries declaratively without brittle side effects on nixos-rebuild switch (ADR-0005 / ADR-0006).  ·  Reading time: ~5 min + 3 retrieval checks.

1. The Packet Path Out of an Orb

Each orb slot plugs into a virtual Layer-2 Ethernet cable called a TAP device (tap-orb1..tap-orb4, created with multi_queue for parallel TX/RX queues[1]). All four TAPs are bridged into a single isolated host switch, br-agent (10.240.0.1/24), with guest IPs 10.240.0.11..14 and public DNS only (1.1.1.1, 9.9.9.9).

The guest itself has networking.firewall.enable = false—the host kernel is the sole security boundary, enforced by table inet agent-isolation in isolation.nft:[2]

2. The Three Architectural Trade-Offs

Trade-Off A: Standalone table inet agent-isolation vs. Extending NixOS's Main Firewall

Why does isolation.nft load its own nftables table at priority filter - 10 instead of appending rules to NixOS's regular firewall?

  • Non-overridable drops: Netfilter evaluates every base chain attached to a hook across all tables, and a drop verdict in any base chain is final.[2] Even if another service or firewall reload opens a port in NixOS's main table, it can never punch a hole through agent-isolation.
  • Fail-closed preflight: Before booting any orb, orb.sh checks nft list table inet agent-isolation. If the table isn't loaded, the VM refuses to start.
  • Trade-off: Two firewall mechanisms coexist on the host (NixOS's main firewall + isolation.nft), so debugging drops requires checking sudo nft list table inet agent-isolation (which conveniently includes live per-rule packet counters).

Trade-Off B: Kernel TAP + Bridge + NAT vs. Userspace Networking (slirp / gvproxy)

Dimension Kernel TAP + br-agent + NAT Chosen Userspace Proxy (slirp / gvproxy)
Enforcement Kernel Netfilter filters every packet by iifname "br-agent" before routing. Policy lives in userspace proxy code; harder to audit with standard nft counters.
Throughput & IPs Native kernel forwarding + deterministic per-slot IPs (10.240.0.11..14). Extra userspace copies per packet; no host-visible per-slot bridge IP.
Privilege cost Requires a root-owned oneshot unit to create br-agent and pre-allocate TAPs for agent-vm. Runs completely unprivileged with zero host network setup.

Trade-Off C: reloadIfChanged = true vs. Standard Service Restart

Why Running Orbs Survive nixos-rebuild switch
In agent-dispatcher.nix, agent-dispatcher-network.service has a preStop hook that deletes tap-orb1..4 and br-agent. If NixOS restarted that unit on a config change, preStop would yank the TAP devices out from under every running orb! Setting reloadIfChanged = true with an idempotent reload = networkScript (ip link show ... || ip tuntap add ... plus atomic nft -f isolation.nft) re-applies rules cleanly while keeping every live TAP fd intact.
